# DevMate 现状

这份文档只讲 DevMate 现在的状态：还没做的、只做了一部分的、没法验证的，以及实测的性能。已经完成的事情不记在这里，它们在代码、测试和[更新日志](../CHANGELOG.md)里。

## 还没做，或只做了一部分

### 连接

- 快速隧道的地址在每次启动后都会变，客户端要换成新地址。地址固定的通路里，OpenAI 隧道只需要所有者在 OpenAI Platform 上建一条隧道（给 ChatGPT 用）；其余几种（自己的中继、Cloudflare 命名隧道、HTTPS 代理、SSH）需要所有者自己的服务器或域名。
- 运行时自己发出的请求（对接 OpenAI 隧道、通路自检、OAuth 客户端信息获取、外部 MCP 服务器）走这台电脑的代理：`HTTPS_PROXY` / `HTTP_PROXY` / `NO_PROXY` 变量，Windows 上没有这些变量时用当前账户的系统代理（开关变化在一分钟内跟上）。还不支持的：代理脚本（PAC）、只有 SOCKS 的系统代理、macOS 和 Linux 桌面的系统代理设置；这几种情况请设置 `HTTPS_PROXY`，体检会指出。连接器子进程（`cloudflared`、`ssh`）和委派的 Agent 只继承环境变量里的代理，不继承 Windows 系统代理。经代理验证过的只有本机替身代理，没有经过真实的 Clash 或公司代理。Node.js 低于 24.14 时运行时照常启动，但它自己的请求不走代理，体检会指出并提示升级。代理工具用 TUN 加虚假地址（域名解析成 198.18.x.x）时，启用了登录（OAuth）的公网地址无法完成登录：登录要核对客户端的真实地址，这道校验不为这种模式放宽，报错里会说明改用系统代理模式或设置 `HTTPS_PROXY`。
- 内置的 OpenAI 隧道客户端不实现“集群纠正”这项可选能力（`wrong-cluster-v1`），也不启动 Cloudflare 托管伴随进程；它只实现文档规定的两种命令，其余种类会被跳过并在体检里指出。
- OpenAI 隧道可以和一条带公网地址的通路同时开（`devmate connect … --openai-tunnel <id>`，或者给现有的通路加上：`devmate connect beside --openai-tunnel <id>`），只在命令行里配置：VS Code 和 Obsidian 的向导里还没有这一项。在向导里改连接会保留已经配好的那条隧道，改成“仅本机”或“OpenAI 隧道”时除外。同时开的时候隧道一律由运行时自己对接，不能用 OpenAI 的 `tunnel-client` 程序。用真实账号试过的只有一种组合：2026 年 10 月，快速隧道加 OpenAI 隧道，两个账号的 ChatGPT 各走一条，进同一个运行时，用的是发布前的构建。其余只对 OpenAI 服务的替身验证过：从外面冒充隧道那一路会被拒，公网一侧要求登录时隧道一路不要求，和快速隧道同开时隧道一路仍然是事件流；中继加隧道、`connect beside` 只在测试里走过，没有对着真实的中继服务器试。
- 自己的中继（`devmate relay setup`）在命令行里配置；VS Code 和 Obsidian 的向导里还没有这一项。中继的服务器脚本支持有 `apt-get`、`dnf` 或 `apk` 的系统，或者已经装了 Caddy 的系统。
- 快速隧道是 Cloudflare 提供给测试和开发用的：不保证可用性，最多同时 200 个请求，不支持事件流。DevMate 经它只回普通 JSON，调用进行中不发进度消息。它适合试用，不适合当日常通路。
- 更换连接方式或地址后要重启运行时。只是保存了新凭据的话，重启连接器就够了（`connection.restart`）。
- 工作台里不能配置连接和登录，也没有一张“现在共享了什么”的清单。
- 工作台的 Now 页（所有项目里正在跑的命令、在干活的 Agent、排队和在跑的任务、等所有者答复的东西，以及谁挂着）只在所有者本机的页面上有，嵌在客户端对话里的工作台没有，连接进来的客户端在两个权限档下都调不了 `runtime.now`。每一类最多列 200 条，旁边写着实际有多少；命令和任务只显示开头 200 个字符；连着的浏览器逐个列出，写明哪个在用、哪个被所有者暂停；停在这一页时每 3 秒重新问一次，因为命令的开始和结束没有事件。这一页是另一个会话写的，在真实浏览器里用临时运行时看过一条在跑的命令和一个等所有者的任务（停止、去答复都点过）；Agent 和任务很多、VS Code 里嵌着的工作台、窄屏都没有看过。
- “谁做的”：每一次会改动东西的调用结束时，在日志里记一行（事件 `operation.called`）：哪个操作、谁要求的（所有者在本机、所有者在编辑器窗口里，或者连接进来的客户端：它自报的名字和它进来的路，本机、公网地址或 OpenAI 隧道）、成没成（没成时带错误码）、用了多久；调用引擎能力时另记能力的名字。调用带的内容一概不记：没有命令、路径、文本；能力的名字和通用调用想调的操作名也是调用方写的，只在它像一个名字（字母数字开头，只有字母数字、点、下划线、连字符，80 个字符以内）时才记，否则这一项整个不记。同一个 operationId 重放的调用算一次调用、不再记一行、不算改动；运行时自己为回答一个调用而做的内部调用（工作台的快照里问供应商和连接状态）不记不算；运行时停止过程中结束的调用照样记。Now 页列出运行时启动以来的客户端（最多 20 个）和最近 50 次改动；项目的活动里和 `event.list` 里也有这些行，在那个项目里干活的客户端读得到。限制：客户端的名字是它自己报的，谁都可以自称“ChatGPT”，不能当作身份，页面上给它加了引号；客户端列表只在内存里，运行时重启就清空（日志里的行留着，随日志的保留期清理）；只读的调用不进日志；编辑器和浏览器宿主在后台按自己的节奏问的东西（`window.*`、`chrome.*`、`host.*`）不记；经通用调用（`operations.call`、`operations.query`）转过去的，按它调的那个操作记和计数，通用调用自己不再记一遍；根本没走到目标的（名字不存在，或者不是这个调用方能要的）按通用调用记一行，带上它想调的名字；客户端那一栏里“改了几次”只算改成了的，失败和被拒绝的不算；客户端或它委派的 Agent 启动的 `devmate` 命令记成一个没有名字、没有来路的客户端；记的是调用结束的那一刻，一次调用启动的东西之后做了什么（客户端启动的 Agent 干了几个小时）不在这一行上。这部分是另一个会话写的，用单元测试和工作台的真实浏览器测试看过，没有让真的 ChatGPT 连进来看它的名字显示成什么。
- Obsidian 里只能设置快速隧道或仅本机。需要域名或凭据的通路要用命令行或 VS Code 配置。
- 浏览器端客户端的来源放行（`allowedOrigins`）只能改配置文件，向导和体检都不涉及。
- VS Code 的连接向导没有步骤计数，也不能返回上一步。
- 没有 ChatGPT 网页里逐步点击的图文步骤。

### 安全与权限

- 在 Windows 上，实例目录放在用户目录之外时，本机其他账户可能读到令牌和凭据。体检会警告，但不会代为设置访问控制。
- 经 ACP 接入的 Agent（Gemini、Grok）没有 MCP 隔离，会加载用户在该命令行里自己配置的 MCP 服务器。
- 委派给 Codex 的会话不带所有者在 Codex 里配置的 MCP 服务器。做法是按名字逐个关掉，并连同 Codex 的 apps（账号的连接器）和 plugins（插件，它们自带 MCP 服务器，`codex mcp list` 里看不到）一起关掉，所以委派的 Codex 会话里也没有插件带来的技能。启动后 DevMate 向 Codex 核对这个会话实际够得着哪些服务器，多出一个就不启动。要让委派的会话照所有者的 Codex 原样运行：`providers.configure {provider:"codex", settings:{inheritMcpServers:true}}`。在 4.0.5 上这套隔离对 Codex 0.161.0 不成立（线程收到的配置会整张表盖掉启动参数里的同名表，被关掉的服务器全都回来了），委派因此要么等满 30 秒超时、要么被判隔离失败；修正后在同一台电脑上实测：只有 DevMate 的通道连着，核对用时约 0.2 秒，会话 1.1 秒就绪。这个修正在 4.0.6 里。
- 读写其他进程内存的逆向工具随安装包一起分发。它们默认关闭，只有所有者在本机才能打开。
- 快速隧道没有登录。地址末尾每次启动新生成的密钥是唯一的凭据：客户端保存了地址就等于保存了密钥，拿到完整地址的人拥有所有者的权限。
- 受保护档不是沙箱：只要共享了一个可写项目，客户端就能运行命令，命令以所有者的系统账户执行。只有全部项目都是只读时，各项限制才是真正的边界。
- 派发先确认（`devmate delegation ask`，默认）拦的是经 DevMate 交给编码 Agent 的任务。有可写项目的客户端仍然可以用命令行工具直接运行 `codex`、`claude`，那同样花所有者的额度，这道确认拦不住。确认只能在电脑前回答：所有者不在电脑前、又没有事先设成 `allow` 时，从聊天客户端派发的任务会一直等着，不设超时（等的时候不启动进程、不占会话名额、不挡 Agent 的其它任务；同时在等的最多 20 个，再多的直接拒绝并说明所有者还有多少个没答；从 `allow` 改回 `ask` 时，已放行但还没开始的任务按先后回到等回答，到 20 个为止，多出来的直接结束并说明）；任务被撤回、Agent 被停止、所在工作流被完成、项目被移出共享、副本里的工作被采纳或丢弃，或运行时重启时，这个问题才结束。在等的任务不计入工作流的轮次，允许时才计。允许的那一刻任务开始不了（这个厂商的会话名额满了，默认 8 个；工作流被暂停或轮次用完了；项目被改成只读；上一个进程还没确认退出），回答会被拒绝并说明卡在哪里，问题原样留着，要等那件事过去后再点一次，或者拒绝；设成 `allow` 时这类任务继续等着并说明在等什么（对来问的客户端和工作台卡片都说），在有会话结束、工作流或项目被改动、会话名额被调高时自动再试并放行。“这个 Agent 之后的任务也允许”说的是它当时的那个会话，只到会话结束为止（停止、进程没了或没起来、运行时重启），空闲 30 分钟断开后要重新问。被拒绝（或被撤回、赶上运行时重启）而且从没启动过的 Agent 会被关闭，客户端要重新派一个，不能接着它派；为它建的工作副本一起删掉，删不掉的（文件夹还被别的程序占着）留在这个 Agent 名下，之后用 `agents.discard` 丢弃；留下了副本这句话对问结果的人只说一遍（任务自己的错误里已经是这句话时，旁边不再重复一遍）。有一种记录这句话不成立：记录指着的地方不在本运行时放副本的文件夹里（状态被手改过，或者做了副本之后实例目录被挪走），`agents.discard` 一律答 `invalid_input`，应用也被拒绝（那个文件夹不在时答 `not_found`），不删文件夹、不动分支，只有把项目移出列表才清掉这条记录；任务没跑成时那句“`agents.discard` 能清掉它”对这种记录是不对的。问题里凡是别人起的名字（Agent、项目、模型、要接续的会话）都放在引号里、压成一行并截短，名字里自带的各种引号一律显示成撇号，客户端选的模型和会话会标明。剩下的只是话术：引号里面的内容扫一眼仍可能读成“一句话结束，后面跟着一条指示”（项目名写成 `Shop'. 档）：客户端交一个带隔离副本的小任务，被告知要等所有者；客户端自己去答应被拒；所有者在本机答应后 Agent 真的运行，客户端拿到结果，读提案并应用；第二个任务被所有者拒绝，以 `delegation_declined` 结束，副本文件夹和分支都清掉。真实的 Codex 没有走过；“这个 Agent 之后的任务也不再问”那个选项、`allow` 和 `off` 两档、因文件夹不在而等待的任务，仍然只用替身 Agent 验证过。

### 运行时

- 事件日志只按保留天数清理，没有大小上限。
- 用过旧的游标重新连接事件流时，没有“中间有缺口”的提示。
- `/health` 不反映连接器正在反复重启。
- `operations.read` 对不带项目信息的历史结果不复查授权。
- `devmate mcp` 收到取消通知时只是转发，上游不会因此停止等待（最长 50 秒）。
- 能力调用（`capability_call`）没有统一的时长上限：浏览器导航最长 120 秒，Godot 的运行和测试最长 15 分钟，都超过客户端对单次工具调用的限制（Claude 240 秒，ChatGPT 据称约 1 分钟）。这类调用要用 `job.start` 作为作业启动，运行时不会自动改走作业。作业用 `job.read` 的 `waitMs` 等到结束（一次最多 50 秒）；输出在作业结束时才记入作业。命令作业运行期间已经打印的内容用 `process_read` 读，进程号在作业的 `processId` 里；能力作业运行期间没有中途输出。这两点只有自动化测试，没有经真实客户端走过。
- 同时连着两个浏览器（比如 Chrome 和 Edge）时，标签页、窗口、书签这些 id 不带“是哪个浏览器给的”。一个浏览器走掉之后，模型拿它给的旧 id 发来的新调用，会发给现在连着的那个浏览器，在那边对应的是另一个东西。已经在排队的调用不会这样改道。同一个浏览器重新连上（它的宿主进程换了一个）时，运行时认不出它是原来那个，排在旧连接上的改动类调用和带 id 的调用会被退回，由调用方重发。
- Windows 上标了“只读”的单个文件，文件工具不替换、不追加、不单独删除（`read_only_file`）。整个文件夹递归删除时，里面的只读文件会一起删掉，和其它文件一样进历史、可以取回：`.git` 里的对象文件就是只读的，拒绝会让带仓库的文件夹删不掉。
- Agent 通道只支持 2025 版握手。
- ACP 适配器按“模式”读取权限设置，没有按协议新的配置项方式实现。
- 保存的状态带格式编号，但还没有在格式变化时升级状态的机制。

### 模型一侧

- 工具清单按客户端分三份（实测，`tests/runtime-surfaces.test.mjs`）：GPT 面 34 项 33,574 字节，Claude 面 36 项 33,830 字节，通用面 37 项 36,144 字节；分面之前是一份 39 项 40,135 字节。只读的工具、能力三件套（`capability_list`、`capability_query`、`capability_call`）和撤回改动都在每一份清单里：曾经为了把清单压到 18 到 21 KB 而把它们挪到 `operations_query` / `operations_call` 后面，那是做差了（模型看不到就不用；只读工具不触发客户端的确认，改走命令行反而每次都要确认），已经改回。每个工具约 500 字节是协议要求的结构（输入模式、四个提示、状态文字）；还想更小只能靠压短描述，这一步没有做。
- 按客户端选工具面还没有用真实的 ChatGPT 或 Claude.ai 验证过：识别靠客户端自报的名字（`openai`、`chatgpt`、`codex`、`gpt` 归 GPT 面，`claude`、`anthropic` 归 Claude 面）、请求的 User-Agent，以及“经 OpenAI 隧道进来的就是 ChatGPT”。说 2025 协议的客户端只在握手时报一次名字，之后的请求只能靠 User-Agent 识别；认错时在 MCP 地址后加 `?tools=gpt|claude|generic` 指定；`devmate doctor` 会显示最近一个客户端自报的名字、User-Agent、分到的工具面和依据，真实的 ChatGPT 和 Claude.ai 报什么名字要到那里看。`devmate mcp`（标准输入输出）会把客户端的名字带给运行时。
- 审阅改动（`show_changes` / `workspace_changes`）只在 Git 仓库里可用：它对比的是上一次提交，“已审阅”按每个文件当前内容的哈希记。不是 Git 仓库的项目只能用改动历史（`workspace.history`）。它只给按文件的汇总，不带差异正文，也还没有可在界面里审阅的差异卡片。
- 命令和委派的默认等待是 30 秒，上限 50 秒，三个工具面一致（`exec_command` 的让出时间也是这两个数）。同类项目记录过“ChatGPT 宿主在约 12 秒处结束调用”，这一点没有用真实的 ChatGPT 实测过；如果实测属实，调用方可以用 `waitMs` 或 `yield_time_ms` 给更短的等待。
- `capability_list` 的 `summary:false` 会一次返回全部结构，体积很大。
- 在 Windows PowerShell 5.1 下，本地化的报错正文可能是乱码，并且会带出实例目录里的脚本路径。装了 PowerShell 7 就没有这个问题。
- 几个入口同时开着时：一个实例只有一个运行时，关掉编辑器、浏览器或终端都不会停掉别人还在用的运行时。运行时因为自己的错误退出（没有被接住的异常）算作意外结束，记录留着，开着“自动启动”的编辑器会把它再启动（十分钟内最多三次），`devmate status` 显示 `crashed`；4.0.5 里这种退出被当成普通的停止，没有哪个入口会因为它意外结束而把它重新启动。端口是实例的，不是哪个入口的：运行时每次起来，启动它的那一方把它用的端口记在实例目录里（文件 `port`），之后任何一次没有指明端口的启动都用这个端口，不管是从编辑器重启、浏览器的“随浏览器启动”、不带 `--port` 的 `devmate start`，还是正常停止之后、意外结束之后。指明的端口优先，并成为新记下的值：命令行的 `--port`，或者编辑器设置里填的端口（见下文）。回到默认端口：命令行 `devmate restart --port 8788`，或者在编辑器设置里填 8788。记下的端口被别的程序占了，照常报端口被占，不会悄悄换一个。`devmate serve`（前台运行）自己不读也不写这个文件，但任何接入它起的运行时的启动（`devmate start`、扩展或编辑器的启动）和任何停止都会把它的端口记成实例的端口。端口文件只在启动、接入、停止时写：升级之前就在跑的运行时（没有新版本的启动器碰过它），第一次从编辑器停止再启动时会在停止前记下端口；意外结束、又没有端口文件时，下一次启动沿用它留下的运行记录里的端口。编辑器里明确设置的端口（VS Code 里 `devMate.runtimePort` 不是空的：这个设置没有自己的默认数字，所以在设置页里填 8788 也会被保存；Obsidian 里端口栏不是空的）算“指明了”，任何数字都算，包括 8788；空着时编辑器不指明端口。以前的 Obsidian 插件保存设置时会把 8788 一起存进去，这样的安装端口栏里显示 8788、也就算指明了 8788：想跟着实例的端口走，把端口栏清空。所有者用 `devmate stop` 停掉之后，运行时仍然会被别的入口再启动：用标准输入输出接入的客户端（`devmate mcp`）下一次请求时、新开一个开着“自动启动”的 VS Code 窗口或 Obsidian 时、开着“随浏览器启动”的浏览器启动时。没有“停了就一直停着”的开关。运行时占着实例、但一时没有回应（超过 1.5 秒）时，VS Code 和 Obsidian 把它当作“忙”并这样显示，窗口和仓库保持挂接，直到它再回应或者进程没了（它回答说自己正在停止或还在启动时不算忙，照它说的显示）；4.0.5 把这种情况读成“没在运行”，会放掉挂接，下一次查看时再重新挂上。运行时是从哪个文件夹启动的，那个文件夹被拿走之后（VS Code 扩展更新会删掉上一版的文件夹）它还会凭内存继续回应，但之后要从那里启动的东西会失败：给 Agent 的通道、Claude Code 的权限请求、浏览器要启动的程序。现在只要是这样，体检有一条失败项（`runtime.files`），`devmate status`、`start`、VS Code、Obsidian、浏览器宿主都会一直说“要重新启动”，不会自动重启；浏览器扩展的面板怎么显示这句话由扩展决定。浏览器为扩展启动的那个程序，在 DevMate 更新之后会自己退出，浏览器随即启动新的。更新有两种样子，都认：它自己的文件被原地改写（全局安装、仓库里的检出），或者浏览器该启动的程序换成了另一个文件（编辑器的扩展每个版本装在自己的文件夹里，运行时启动时会把浏览器该启动哪个程序记下来）；两种都要连续两次看到才算。只是文件没了、又没有别的程序可启动时它不退出。进程真的结束这一点用构建出来的程序和真实的子进程测过（改写文件、改登记，各一次；登记的程序不存在时留着）。其余几条（文件夹被拿走后的提示、“忙”）只用模拟的状态测过，没有真的在 VS Code 里做一次扩展更新来看。“文件夹没了”只认系统说“不存在”，磁盘一时读不到不算。运行时启动时会逐个确认上一个运行时留下的命令进程是不是原来那个再结束它（Windows 上每个约 0.3 秒，一个接一个），启动的上限是 20 秒，所以留下五十个以上时启动可能超时；这只量过耗时，没有真的留下那么多试过。
- Windows 上浏览器启动 DevMate 用的是一个命令文件。家目录、实例目录或 DevMate 自己的路径里有中文（或别的非 ASCII 字符）时，4.0.5 写出的这个文件被 Windows 按系统代码页读，路径变成乱码，什么都启动不了，扩展只会说连不上 DevMate，没有原因。现在文件开头（第二行）先声明按 UTF-8 读，运行时下一次启动时会重写这个文件。用一个名字带中文和空格的家目录实测过（改之前启动不了，改之后启动并拿到正确的参数）；macOS 和 Linux 上是 shell 脚本，没有这个问题。
- 用 winget 或商店装的 PowerShell 7 是应用包：`pwsh.exe` 不是文件，而是 Windows 放在 PATH 上的一个名字（应用执行别名）。4.0.5 在这样的电脑上找命令行时直接出错，运行时启动不了（这时的体检只能说运行时没在跑，原因在运行时的日志里）；而体检建议的那条 winget 命令装出来的正是这种。现在这种名字能被找到并启动，用的是这个名字本身而不是包所在的带版本号的文件夹（那个文件夹会随商店的自动更新消失）。在所有者的电脑上用 PowerShell 7.6.6 实测过：带中文和空格的项目路径、往项目里写文件、`env` 传变量、`a && b`、非 ASCII 输出、`tty` 下往程序里写入、超时终止、`process_stop` 结束整棵进程树（含子进程）。没装 Python 的电脑上 Windows 自带的 `python.exe`、`python3.exe` 占位名字（打开商店的那个）不算程序；这一点只在测试里模拟过，实测的电脑装了真的 Python。PATH 上别的这类名字（`bash` 指向 WSL、`winget`、`wt`）照在终端里那样启动。带输入的命令（`tty`、`interactive`）能往程序的标准输入里写；PowerShell 自己的 `Read-Host` 不行（命令行是以非交互方式启动的，它报错后命令继续，得到空值），5.1 和 7 都一样，工具说明里这样写了。体检和报错里给所有者的其它安装命令（`winget install BurntSushi.ripgrep.MSVC`、`Git.Git`、`Cloudflare.cloudflared`，以及 macOS 和 Linux 上的 `brew`、`apt`）这一轮没有照做过。
- MCP 引导请求（elicitation）用于审批、MCP Events、`.mcpb` 打包、MCP Registry 的 `server.json` 都没有做。
- 没有子目录脚本发现、标准输出与标准错误分开的进程输出、上下文包导出和命令行交互模式。
- 编码 Agent 的接入是代码，不是配置：新增一种 Agent 要改代码。
- 委派默认仍然直接在项目里改文件；要先看差异再应用，得在委派时加 `isolate:true`。隔离副本从最后一次提交开始，不含未提交的改动和被忽略的文件：依赖要在副本里重新安装才能跑测试，项目还不能预先配置“副本准备步骤”，委派结果里会说明副本缺什么。副本没有过期清理：运行时崩溃或 Agent 被丢下不管时，副本目录和 `devmate/copy-…` 分支会一直留着，直到应用、丢弃或把项目移出 DevMate；体检也还不列出现存的副本。工作台里还没有查看、应用和丢弃提案的界面。副本里 Agent 自己的权限请求照常要批准。
- 成组撤销（`workspace_restore` 的 `since`）覆盖 DevMate 自己的文件工具做的改动，以及从隔离副本应用进来的改动。不隔离的 Agent 和命令直接改的文件不在这份历史里，要靠 Git。
- 没有免安装的试用方式：命令行没有发布到 npm（发布流程里有这个作业，仓库没有配置 npm 凭据所以跳过），要从 Releases 下载安装包。
- 脱敏报告（`devmate doctor --report`）只能去掉它认得出的东西：凭据的常见写法、家目录和账户名、共享文件夹、公网主机名、IP 和邮箱。日志里其他形式的私人信息要靠发出去之前自己看一遍。VS Code 和 Obsidian 里还没有对应的命令。

### 界面

- 活动页的“Load earlier”按全局序号每次回退 300 条。在很忙的实例里，安静项目往前翻会很慢。
- 同一个概念的叫法没有完全统一：VS Code 的命令 ID 和工作台里仍然叫“project”，其他地方叫“共享的文件夹”。
- Obsidian 的笔记索引没有在元数据缓存就绪之后做一次全量刷新。
- Obsidian 插件把运行时源码以可读的纯文本内嵌在 `main.js` 里（约 10.6 MB），不是瘦客户端。
- Obsidian 写到实例目录里的运行时文件，换版本后旧的那一份不会清理。

### 测试

- 测试里还有靠短时限判断超时的用例。其中两个在繁忙的机器上失败过（准备数据的普通调用也被套上了 0.3 秒的时限），已经改成只给应当超时的调用设短时限；其余用例没有逐个排查。

## 有意保持的设计

这些是决定，不是遗漏。要改的话都是很小的改动。

- 权限档默认是“受保护”。“完全访问”由所有者在自己的电脑上打开。
- VS Code 默认把打开的受信任文件夹以读写方式共享，Obsidian 的共享询问默认选中“读写”。
- 编辑器窗口可以修改实例级的设置，因为它是所有者在本机的入口。
- 家目录不能作为项目共享，因为运行时自己的状态在里面。
- 有多个项目时，每次修改都要指明项目；不按会话记住项目。
- 覆盖文件的操作不标记为“破坏性”，因为被覆盖的版本可以恢复。
- 带正文的工具结果只有文本一种表示，所以工具不声明 `outputSchema`。
- 任务和消息是用户数据，不会自动清理。

## 没法验证的

- OpenAI 隧道在 2026-10-12 第一次用真实的隧道 ID 和运行密钥连通：服务接受了这个运行时（体检显示已连接、正在等活），随后真实的 ChatGPT（建隧道的那个账号，免费版）经它调用了一次 `project_list`，得到了正确的回答，运行时计到 4 次到达的调用。除此之外，内置客户端是按 OpenAI 公布的协议文档和接口定义实现的，用假的控制面验证过（取任务、普通应答、带进度的流式应答、通知、会话结束、超时、重试、并发上限，以及经真实运行时返回真实工具列表）。带等待时限的调用（真实服务发来的调用应当都带）在 4.0.5 发布前的代码评审里才被发现完全不会被应答：剩余时间是带小数的毫秒数，而定时器只收整数，此前对假的控制面的测试只覆盖了“立刻过期”和“不带时限”两种，所以没有碰到；已修，并补了带时限的普通应答、流式应答和重发应答三种测试。对真实服务量过“要活干”的请求多久返回（同一把密钥、同一条隧道）：请求等 1000 毫秒，5576 毫秒后返回；请求等 5000 毫秒，5425 毫秒后返回；请求等 30000 毫秒，30414 毫秒后返回。也就是服务最短也要等大约 5 秒。4.0.5 发出去的版本给启动后的第一次请求总共只留了 6 秒，所以头一两次请求可能被它自己掐掉，体检里短暂显示“连接中”并误说成连不上 api.openai.com，随后才是“已连接”；4.0.5 之后改成给 16 秒，并把“到时间还没回”和“连不上”分开说，这个修正在 4.0.6 里。带等待时限的调用（上面修的那一处）由此在真实服务上成立；带进度的流式应答、并发上限和重发仍然只对假的控制面验证过。个人账号（免费版）在 ChatGPT 里可以选到“隧道”这种连接方式。个人账号的隧道只能给同一个账号的 ChatGPT 用：把另一个个人账号的工作区加进隧道时，OpenAI 的页面提示无法验证该工作区与组织的关联，保存不了；那个账号的 ChatGPT 选这条隧道会被 OpenAI 拒绝，请求到不了 DevMate。被拒绝时的提示按 OpenAI 公布的错误码表写（隧道 ID 格式、需要指明组织、密钥无权使用这条隧道），同样只对假的控制面试过；指明组织用的是 OpenAI 自己的客户端所发的 `OpenAI-Organization` 请求头，接口定义里没有写它。OpenAI 没有为“协议版本过旧”公布错误码，所以这一条是按状态码 426 和答复里的措辞认的，认不出时原样给出答复，不猜原因。OpenAI 自己的客户端目前用的协议版本和 DevMate 相同（2026-08-25）。

- Windows 不替换任何还被别的程序开着的文件，哪怕那个程序允许移动和删除它。DevMate 原先把新建的文件做成它的工作副本的第二个名字（硬链接），结果扫描程序还开着工作副本时，刚建好的文件就替换不了：在一台很忙的电脑上实测，这样建的 2400 个文件里有 19 个在一分钟以上都无法替换。现在在 Windows 上新文件是它自己的一个文件（独占复制），同样的负载下 2400 个里 0 个；再用产品自己的新建、覆盖、编辑在 6 个进程里并行做了 7200 次改动，0 次失败，没有留下工作副本。另外，要替换的文件正被别的程序开着时（编辑器、监视文件的服务、扫描程序），DevMate 把旧文件挪到一边、把新文件放到位、再删掉旧的，不用等；这中间有一瞬间该名字下没有文件，新文件放不上去时旧文件会放回原处。只有连挪都不让挪的程序（独占打开）才需要等：整个改动隔一会儿重做一次，最多 20 秒，等待期间运行时照常处理别的请求，超过了就报“文件被别的程序占着”（`file_busy`），什么都没改；超过这段时间仍被拒绝时，报错里会说明这多半是有程序一直开着它，或者是这个账户没有改它的权限（Windows 对这两种情况给的是同一个答复，DevMate 分不出来）。标成只读的文件不算：写入、编辑、补丁、追加、覆盖式移动和删除都立刻拒绝（`read_only_file`），并说明要先去掉只读标记。旧文件被挪到一边之后既换不上新文件、也放不回原处时，原名下就没有文件了：报错（`file_displaced`）会给出旧内容所在的那个工作副本的名字，它不出现在文件列表里，要用命令移回去；这条路只用替身测过。被挪开的旧文件一时删不掉时（有程序把它映射在内存里），运行时在之后的每次改动时再删一次；运行时重启后留下的这类文件（名字以 `.devmate-write-` 开头）不会再有人清，`git add -A` 会看到它们。追加（`append`）不走替换：文本直接加到文件本身的末尾，开着这个文件写日志的程序不受影响。删文件夹删到一半被占住时，报错（`delete_incomplete`）会说已经删了几个、能不能找回，同一个调用再来一次删掉剩下的。“挪到一边”和“等到放开”这两条在 Windows 上各用一个真的开着文件的程序实测过。运行时自己的小状态文件（配置、凭据、运行记录）不能有一瞬间不存在，不用“挪到一边”，仍是原地重试约 5 秒，那段时间不处理别的请求。

- 用网页组件（shadow DOM）搭的页面，在 4.0.6 里：4.0.5 在这类页面上，元素结构里列得出按钮，按编号点却被当成“被别的元素挡住”（挡住它的是它自己所在的组件），按文字找不到元素，按文字等也等不到。改成：按文字找元素和按文字等待也看进组件里面，直接写在组件里的文字、插槽自带的后备文字、只把内容透传出去的包装（display: contents）里的文字都算；判断挡没挡住时，先问浏览器那个点上到底是哪个节点（`DOM.getNodeForLocation`，只读；它连封闭组件里面的也说得出，页面脚本只看得到组件的外面），再让页面判断这个节点是元素自己、在它里面还是围着它，页面交给组件插槽的内容算在组件里面；问浏览器时加上页面滚动到的位置（浏览器按文档里的点算，鼠标和元素的盒子按窗口里的点算；不加的话，在滚动过的页面上浏览器回答“那里没有节点”而一直走退路，滚动量小于目标在窗口里的纵坐标时回答的则是另一个节点，这只在本地的提交里存在过，没有发布）；浏览器交回来的不总是元素，直接写在组件里的字交回的是组件的那棵树，由组件代表，`::before`、`::after` 这种没有自己元素的部分交回的不是节点，这时问页面它属于哪个元素，属于目标自己不算挡，属于围着目标的元素（包装层用 `::after` 画的遮罩）算挡；交给页面的节点句柄用完就还给浏览器；所以组件自己的遮罩盖住页面交给它的按钮、页面交给同一个组件的另一块内容盖住组件里的按钮，都会被拒绝并点名（上一版这两种会点到遮罩上却回答点到了）。不显示的东西不算找到：只把内容透传出去的宿主在不显示的容器里、或者被隐藏时，按文字等不到也找不到；插槽已经被给了内容时，它自带的后备文字不算；并排的几块（“Total”和“: 5”）带空格、不带空格两种读法都试。现在的限制：封闭的组件（不让页面脚本看里面的）里的元素按文字找不到、等不到，只能按元素结构里的编号操作；CSS 选择器只找页面自己的那棵树，组件里面的找不到；一个页面看进 2000 个组件，超出时按文字等待的超时说明里会说“文字可能在其余的组件里”；分散在几个元素里的词，在只透传的包装里或直接挂在组件下时，等得到但按文字点不到（没有可点的位置）；按文字找时顺着只透传的层最多往外走五步，绝不落到整个页面上；浏览器说不出点上是什么的时候（很少：点不在显示范围内，或点上是页内框架里的东西）退回页面自己的说法，那时封闭组件里“盖在它给出的内容上面的自己的遮罩”看不见，组件里再套一层组件时内层自己的遮罩也看不见；一段文字的 `::first-letter` 盖在它开头的短链接上时，那个链接可能被当成被挡（按页面说出的元素判断，这种排版没有在真机上试）。另外几条：双指放大并平移过的页面上，问浏览器时加的是布局视口的偏移，和鼠标去的点差一个平移量，可能把别的元素当成遮挡或漏看（浏览器菜单里的缩放不受影响）；点一个“自己用 `::before` / `::after` 画了覆盖层的链接、按钮或卡片”里面的子元素会被拒并点名外层那个元素，点外层即可（之前点得到，落在外层上）；`page.inspect` 问浏览器用的是第一个盒子的中点，问页面用的是整个外框的中点，折成两行的链接第一个盒子正中是它自己的 `::before` 图标时，`coveredBy` 可能报成它外面的段落，只影响读。测试上还缺的：只读名单的测试没有让 `page.inspect` 走到底；交回 Document 的那条断言新旧代码都过；`page.inspect` 里“不是节点”的分支、取不到布局视口时的退路、两次调用都失败时的释放，没有测试。页面里的框架（iframe）每一个都在元素结构里列出（没有名字的框架原先整个不出现），地址只为列出的前 100 个去问，之后的不带地址，并且只显示标签页打得开的地址（http、https；`javascript:`、`data:`、`blob:` 的不显示）；还没加载的框架按它要加载的地址显示，内容直接写在页面里的框架（srcdoc）没有地址；框架里面的内容仍然读不到也操作不了，可以用 `tabs.open` 把那个地址单独打开，站点不让单独打开的就没有办法。按文字等待超时不等于页面上没有：框架里的和封闭组件里的不看，超时的说明里这样写。这些是另一个会话在一次性配置的 Chrome 154 里用真实网页逐条试的（Windows）；Edge、macOS、Linux 没有试。
- Windows 上的注册经系统自带的管理服务（WMI 的 StdRegProv）读写当前用户的注册表，而不是 `reg.exe`：在打包应用里运行的程序（例如某些应用内置的终端）拿到的是 `HKCU\Software` 的一份私有副本，从那里用 `reg.exe` 写进去的注册浏览器永远看不到。这是在真机上撞到之后改的，改后的读取在同一台电脑上实测过（约 1 秒），写入和删除只用替身测过。注册只存在于那份私有副本里时，`devmate chrome` 报“未注册”并说明原因，重新执行 `devmate chrome install` 即可；卸载会把两处都清掉。
